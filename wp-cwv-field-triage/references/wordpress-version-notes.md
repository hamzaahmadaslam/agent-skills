# What changed by WordPress release

Read the site's version first (`wp core version`) and apply the rows at or below it. A fix that relies on a newer
release needs an update first, as its own change on staging. Current release when this skill was last verified
(2026-09-26): 7.1.2 ([WordPress version check API](https://api.wordpress.org/core/version-check/1.7/)).

## What this means for the triage

- Before 6.3: no core way to defer plugin scripts, no automatic `fetchpriority`, and a lazy-load threshold of 1, so
  the second image in a multi-column layout could be lazy. Plan the update first.
- Before 6.8: no core speculative loading; the Speculative Loading feature plugin offered it
  ([Speculative loading in 6.8](https://make.wordpress.org/core/2025/03/06/speculative-loading-in-6-8/)).
- Before 6.9: classic themes print the full block library CSS unless they opted in to separate block styles, and those
  styles then load in the footer; `fetchpriority` for scripts is not available.
- On 6.9 and later: a classic theme that opted out of the template enhancement output buffer, or a plugin that returns
  false from `should_load_separate_core_block_assets`, loses the on-demand block CSS
  ([6.9 frontend performance field guide](https://make.wordpress.org/core/2025/11/18/wordpress-6-9-frontend-performance-field-guide/#load-block-styles-on-demand-in-classic-themes)).
